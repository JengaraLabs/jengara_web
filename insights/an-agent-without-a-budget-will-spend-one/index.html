An agent without a budget will spend one

By Frank Ribeiro, Jengara · 27 November 2026 · Product and engineering notes

An agent budget is a limit on what one run, one agent and one team may spend, enforced before the next model call is made. Without it, an agent does not have a cost problem waiting in a future invoice. It has standing permission to spend whatever its loop decides.

Research approach

Jengara reviewed the Gartner forecast on agentic AI project cancellations from June 2025, the LangChain State of Agent Engineering survey of more than 1300 professionals fielded in late 2025, the Anthropic engineering account of its multi agent research system from June 2025, the OWASP guidance on unbounded consumption, and the Vercel production index on model spend. Vendor figures are attributed where they appear.

Why agent cost grows faster than the work

Anthropic reports that agents typically use about four times the tokens of a chat interaction, and that multi agent systems use about fifteen times the tokens of a chat. That is the healthy case, with the system working as designed. The reason sits in the loop. Each step sends the growing history back to the model, so later steps cost more than earlier ones even when the task has not grown.

Production data points the same way. Vercel reports that requests using tools grew from 31.6 percent to 58.9 percent of all tokens on its AI Gateway between October 2025 and April 2026,

A budget that reports is not a budget

Many teams believe they have a budget because a dashboard shows spend and an alert fires when a threshold passes. Vercel draws the line clearly. Spend alerts show that something is wrong, while budgets set per key enforce. When a key passes its cap, further requests are rejected rather than reported. An enforced cap bounds the run itself.

Placement matters as much as enforcement. A cap on a shared provider account stops every agent at once and says nothing about which one spent the money. A cap held per agent, per team or per customer makes spend attributable and keeps the blast radius small.

The financial risk is now a board level fact

In June 2025 Gartner predicted that over 40 percent of agentic AI projects will be canceled by the end of 2027, and it named escalating costs first among the reasons, ahead of unclear business value and inadequate risk controls. None of the three is a complaint about model quality.

Adoption widens the exposure. LangChain found that 57.3 percent of respondents already had agents in production, Vercel adds the paradox for finance teams. Total spend on its gateway grew 43 percent in a single month in May 2026 while prices per token held steady, because workloads moved toward heavier models and more tool use.

Security teams already have a name for this

OWASP lists the risk as LLM10, unbounded consumption, Excessive and uncontrolled inference leads to economic loss, and an attacker can exploit pay per use pricing to impose unsustainable costs. The attacker is optional. A tool that keeps failing, a verifier that never accepts an answer, or two agents handing work back and forth will produce the same invoice with no adversary involved.

That framing changes where the control lives. The limit cannot sit inside the agent code alone, checked by the same process that is misbehaving. It belongs in the path every call must travel, in the gateway or orchestration layer, where the next call can be refused before money leaves the account.

Set budgets at four levels, and check before the call

Start with the run. Give every run a maximum number of steps, a maximum spend and a maximum running time, set a little above what successful runs actually use. Add repeated call detection, so a tool called with the same arguments again and again, or failing again and again, stops the run or hands it to a person.

Then set the wider levels. Give each agent its own key and allowance, so identity and spend travel together. Set a team or customer level budget that protects shared funds, and keep the provider level cap as the final backstop. At each level, check before the call is sent. A budget checked after the call is an accounting entry. A budget checked before the call is a control.

Judge the budget by cost per successful task

A cap alone can make an agent cheap and useless. The measure that keeps cost honest is cost per successful task: total spend in a period divided by the number of runs that passed evaluation in that period. Production summaries put cost per resolved task between five cents and thirty cents in most cases, with observability reported at 15 to 25 percent of model cost. Count both, or the budget will reward runs that finish cheaply and fail quietly.

Review the distribution, not only the average. Averages hide the long tail where loops live. Look at the most expensive one percent of runs each week and tighten the limit that would have caught each loop behind them.

Jengara decision rule

Give every agent a budget it cannot talk its way past: a step limit, a spend limit and a time limit on each run, an allowance on its own key, and a provider cap behind both. Enforce each limit before the next call, outside the agent itself, and judge the system on cost per successful task.

Executive takeaway

Escalating cost is the first reason Gartner expects agentic projects to be canceled, and it is the most preventable. Agents overspend because nobody set a limit that binds at the moment of spending. Set the budget where the call is made, and the invoice becomes a record of a decision instead of a surprise.

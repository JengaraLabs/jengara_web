Each agent passes. Together they fail.

By Frank Ribeiro, Jengara · 11 November 2026 · Product and engineering notes

A multi agent system is a workflow in which several specialised agents hand work to one another to complete one task. Each agent can pass its own evaluation and the composed system can still fail most of the time. The unit that ships is the system. The unit most teams test is the agent. That mismatch is now measurable.

Research approach

Jengara reviewed the Google Research paper Towards a Science of Scaling Agent Systems, the MAST failure taxonomy published as Cemri and colleagues in 2025, the VentureBeat Pulse survey of 157 enterprises from June 2026, and the LayerLens synthesis of that evidence from September 2026. Every figure in this note traces to one of those sources.

The maths compounds quietly

Take a workflow of twenty steps in which each step succeeds 95 percent of the time, a rate most teams would accept in isolation. LayerLens shows the composed workflow succeeds about 36 percent of the time. At 90 percent per step it succeeds about 12 percent of the time. Five agents at 90 percent each give success near 59 percent. Nothing here needs a weak model. Ordinary reliability, multiplied across enough handoffs, produces an unreliable system while every individual report stays green.

Failures live between agents

The MAST taxonomy examined 1,642 execution traces across seven multi agent frameworks and sorted failure into three families. Specification problems account for 41.77 percent of failures, coordination failures for 36.94 percent, and verification gaps for 21.30 percent, in the breakdown LayerLens reports. Across the systems studied, failure rates ranged from 41 percent to 87 percent.

Read the families plainly. Specification means agents received tasks that were ambiguous, incomplete or in conflict, and each resolved the gap by guessing. Coordination means agents acted on stale or conflicting shared state, so an action that looked right on local information was wrong for the system. Verification means no agent checked the work it received before building on it. None of these faults appears when an agent is tested alone with a clean prompt and a fixed input.

Coordination decides how far errors travel

Google Research evaluated 180 configurations across five architectures, three model families and four benchmarks, holding tools and budgets steady. Independent agents amplified errors 17.2 times over a single agent baseline. Central coordination contained that amplification to 4.4 times, because an orchestrator can spot inconsistency and retry a failed handoff.

Architecture also decided whether more agents helped at all. Central coordination improved work that splits into independent parts by 80.9 percent, while sequential multi agent planning fell 39 percent to 70 percent below a single agent. LayerLens adds that one compromised agent can infect 89 percent to 100 percent of downstream agents through shared state, and only 14 percent of production deployments use formal orchestration, even though orchestrated systems show failure rates 3.2 times lower.

Enterprise tests already show the gap

VentureBeat Pulse surveyed 157 enterprises in June 2026 and found that 50 percent had deployed an agent or model feature that passed internal evaluation and then caused a failure for a customer, with a quarter reporting it more than once. Only 5 percent said they fully trust automated evaluation today, and the limitation named most often, at 29 percent, was poor alignment between evaluations and real world outcomes. Yet 66 percent already allow deployment on automated evaluation alone for some agents, or are building pipelines to allow it within twelve months. Only about a quarter run real time quality checks on live production traffic. Autonomy is rising on tests their owners describe as weakly aligned with reality.

Test the system you will ship

Evaluate complete traces, not agent scores alone, and sort every failure into specification, coordination or verification before anyone proposes a stronger model. A distribution tells leaders where to intervene.

Measure reliability at each handoff as well as for the whole task, and validate what crosses each boundary, checking fields, ranges and fitness for the original goal before downstream work begins. Run the composed system under load and under fault, including slow responses, stale state, missing inputs and a wrong upstream result presented as fact. Give one coordinator authority over shared state and routing, and give verification to a checker that the producing agents cannot overrule. Gate promotion on repeated end to end runs on real tasks, in the exact configuration that will ship, and keep the same trace discipline in production.

Jengara decision rule

Approve a multi agent system only when the composed system, in its shipping configuration, has passed repeated end to end evaluation on real tasks, with failure sorted by cause, reliability measured at each handoff, one coordinator in control and an independent check before action. If a team can show only that each agent passed alone, the system has not been tested. Treat it as untested, however strong the individual scores look.

Executive takeaway

The question has moved. Leaders no longer need to ask whether each agent is capable. They need to ask whether the system those agents form together has ever been measured as a system.
